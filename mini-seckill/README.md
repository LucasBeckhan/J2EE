# 迷你秒杀系统（第一阶段）

学习入口：[从一次点击读懂整个项目](学习导读.md)，包含阅读顺序、完整调用链、事务与并发示例、前端状态说明和断点建议。

这是一个便于本地学习的同步下单版本，重点演示 Spring Boot 分层、数据库事务、条件扣库存和唯一约束防重复。代码中的关键业务步骤都附有中文注释。

## 启动

需要 JDK 8 和 Maven。在项目根目录运行：

```bash
mvn -f mini-seckill/pom.xml spring-boot:run
```

启动后会自动创建 H2 内存数据库，并添加耳机（100 件）、键盘（50 件）、保温杯（80 件）、台灯（30 件）四种演示商品。应用重启后内存数据库会重置。

## 接口

```text
GET  http://localhost:8080/api/products
POST http://localhost:8080/api/products/1/seckill?userId=1001
GET  http://localhost:8080/api/users/1001/orders
```

可以重复调用 POST：同一个用户对同一商品只能成功一次；库存耗尽后会返回 HTTP 409。演示时的 `userId` 只是简化参数，不能用于真实鉴权。

## 并发正确性设计

- 库存通过 `UPDATE ... WHERE stock > 0` 一次性原子扣减，不采用 Java 先读后改。
- 库存扣减和订单插入处于同一个数据库事务；订单插入失败时库存变更回滚。
- `(user_id, product_id)` 唯一约束防止同一用户重复购买，处理并发竞态。
- 本阶段是单体同步实现，还没有 Redis、消息队列、登录鉴权、支付、超时取消和分布式限流；它是学习版本，不代表能承载大规模线上秒杀流量。

## 后续迭代建议

1. 加入请求参数校验和登录鉴权。
2. 增加 Redis Lua 预扣库存与防重复请求。
3. 增加消息队列及有界订单消费者线程池。
4. 增加订单超时取消、库存释放、重试和对账。
5. 用并发压测验证“成功订单不超过库存、用户不重复下单”。
